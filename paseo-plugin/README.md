# CodeyLink 手机插件

提供两个手机端补充能力：把 CodeyLink 生成的「用户附件」图片块转换为靠右排列的 84×84 卡片；以及复用当前 Codey 的提示词优化配置。图片默认只读取小缩略图，点击后才从电脑获取原文件；原图按屏幕宽度打开，长图纵向滚动，可用「放大 / 缩小」调整比例。展示裁掉缩略图画布的填充部分，不裁掉图片内容。

## 安装

电脑 Paseo daemon 和手机 App 均需 **0.8.x**。插件通过 Paseo 官方插件接口加载，无需修改 APK。版本范围是插件接口要求；桥接的整体验证范围以 [COMPATIBILITY.md](../COMPATIBILITY.md) 为准。

1. 升级电脑与手机 Paseo 后，用本项目停止、启动入口重新启动专用 daemon。Codey Desktop 保持运行。
2. 在项目根目录执行：

   ```powershell
   node tools/paseo_mobile_plugin.mjs install
   ```

3. 打开这套专用服务的 **Settings → Plugins**，开启 **Enable plugins** 和 **codey-link-mobile**。全局开关也会启动其他已启用的插件。
4. 在手机上退出、重新进入会话。已有缩略图第一次使用新版桥接时会补建本地附件索引。

安装入口使用 `.paseo-codey/connection.json` 确认专用服务的目录、端口和版本，不会启动另一个 Codex 后端。安装的是当前目录源码，移动仓库后需要重新安装。

## 配置与维护

在项目根目录 `.env` 中配置，修改后重启专用 daemon：

```dotenv
# 插件主动打开一张原图的上限，单位 MiB；范围 1–1024。
CODEY_LINK_IMAGE_OPEN_MAX_MIB=20
```

自动预览沿用主项目的最新消息优先预算。缩略图每张至多 256 KiB，客户端短期缓存缩略图；原图关闭后不保留在插件缓存中。提高上限会增加手机内存和网络用量。这里的上限只约束插件读取，旧版 Paseo 的文件入口不受它控制。

```powershell
node tools/paseo_mobile_plugin.mjs status
node tools/paseo_mobile_plugin.mjs reload
node tools/paseo_mobile_plugin.mjs disable
```

禁用后恢复原来的 Markdown 附件块，并移除优化入口。普通文件和超过自动预览预算的图片保留原展示。历史中的混合附件整条保留原展示；实时消息被 Paseo 拆段时，只转换可识别的图片段，保留文件入口与错误说明。

## 提示词优化

在会话里使用 `/optimize 原始需求`，或打开命令中心的「Codey 提示词优化」。优化请求由专用 daemon 调用当前 Codey Desktop 已启用的优化器，模型、规则和凭据始终留在 Codey 中；它不会新建 Codex 后端，也不会把草稿自动发给当前会话。

优化面板会保留原文并提供可编辑结果。只有点击「确认发送」才会向打开面板时的原会话发送一次；也可以复制结果后自行粘回原生输入框。每个优化作业的结果在内存中保留 5 分钟，最多保留 20 项；重新打开面板可以恢复未过期结果。重启 daemon 或重载插件会清除这些临时结果，发送状态不确定时应先检查原会话。

Paseo 0.8 的公开插件接口无法读取或替换主输入框草稿，也不能接收主输入框的附件。因此当前仅优化文本；需要附图或文件时，保留在原消息框中，复制优化后的文字回去再发送。

## 数据与边界

- 图片卡片只转换桥接生成且带明确标识的附件行。它仍是用户消息之后的一行，不修改 Paseo 原生用户气泡，也不重写历史或发送新消息。
- 同时识别完整历史消息和实时 Markdown 分段。新图片的缩略图与原图入口在同一段内传递；已缓存的旧图片段也可转为小卡片，其独立原图链接继续保留。
- 手机传给服务的是附件标识；服务从本地 `.paseo-codey/image-previews/` 索引解析文件，检查文件大小、修改时间和图片格式。缺失、超限或变更时显示错误，不尝试猜测文件。
- 本地索引含原图路径，仅存放于被 Git 忽略的运行目录。插件源码和发布包不包含图片、索引或配对信息。
- 当前通过官方 0.8.0 编译器、独立 daemon 的真实 RPC 和 390px Web 渲染验证。提示词优化已用当前 Codey 的真实优化器验证，结果恢复不会重复提交；专用服务实际会话的命令中心入口和面板也已验证，验证过程没有向会话发送任务。安卓 App 的插件加载、底部面板手势、冷启动历史恢复与 relay 网络仍需实测。此结论不等于全链路升级已通过。
