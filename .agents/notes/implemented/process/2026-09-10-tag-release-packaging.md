# Agent Note: 按标签发布源码运行包与兼容性记录

Status: implemented

## Problem

项目和被适配组件分别升级。发布包如果读取当前工作区或主分支文档，旧标签可能携带错误的适配说明；直接压缩目录还可能混入运行凭据和会话。

## Decision

[打包脚本](../../../../scripts/build_release.py) 固定目标标签对应的 commit，逐个读取明确清单中的 Git blob，生成 Windows ZIP、SHA-256 清单和发布说明。ZIP 使用固定时间戳，CMD 转为 CRLF，并附带 tag / commit 元数据。兼容性说明选取标签内历史表中基线与 tag 匹配的行，并附带运行条件和验证边界，没有匹配基线时停止。历史日期使用单个提交日期，升级过程与逐项检查放入 Git 提交说明；发布前先更新本次历史记录的基线及项目版本，提交后再打 tag。

旧标签保留原始文档；打包脚本继续支持其“当前验证记录”格式，补发旧版本无需修改或重打标签。

图片运行模块、配置样例及手机插件使用明确文件清单。旧标签不含这些功能时仍可重建；引用图片模块却缺文件、或插件文件不完整时拒绝打包。Codey 版本字段支持闭区间写法并校验上下界，发布说明原样保留区间。

Codex CLI 字段允许 Desktop 实际携带的预发布版本，例如 `0.154.0-alpha.6.2`，其他组件的版本校验保持原样。发布说明保留完整后缀，不能将 alpha 后端误写为稳定版。聚焦测试覆盖合法后缀、空后缀、空分段和无效字符拒绝。

[workflow](../../../../.github/workflows/release.yml) 支持 tag push 和手动输入已有标签，因此旧的 0.0.1 无需重打标签。它运行隔离打包测试及目标标签的策略测试、语法检查，创建含附件的草稿后再发布。已有同名 Release 不覆盖；失败草稿由维护者检查后删除重跑。

## Verification

本地隔离 Git 仓库测试覆盖未提交改动不入包、非清单文件排除、CRLF、校验和、重复构建一致性、缺失标签、历史行筛选、多组合匹配、单日期及版本字段校验。另以现有 0.0.1 标签实际打包，验证旧文档兼容读取。GitHub 托管 runner 与 Release 上传结果需要单独核对；这些测试不扩大应用兼容承诺。

区间解析测试使用固定的最小历史表，不依赖工作区文档何时更新。代码与 README、COMPATIBILITY 分步提交时，仍可使用提交内的旧文档完成全部隔离发布测试；这不代表新代码已打标签或发布。

## Alternatives considered

- 直接打包工作目录：容易夹带本机数据，且不能保证与 tag 一致。
- 在 workflow 硬编码组件版本：发布旧标签时会被新值污染。
- 为已有标签重打 tag：破坏已发布源码定位，采用手动触发兼容旧标签。
- 自包含 EXE：需要额外打包运行时与第三方依赖，目前交付明确依赖的源码运行包。
- 测试直接断言当前兼容文档包含某个区间：文档延期提交会使代码测试失效；改用固定用例验证解析规则，实际打包继续读取目标标签文档。

## Consequences

产物与兼容记录都可追溯到同一提交，也能为旧标签补发包。代价是新增运行文件时必须维护清单，更新项目版本时必须同步兼容记录；首次上传或失败草稿仍需要维护者查看 Actions 结果。
