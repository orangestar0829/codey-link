# Agent Note: 用户普通附件按需打开

Status: implemented

## Problem

Codex 的用户文件附件包装在 Paseo 历史中变成普通路径文本；已有的回复文件链接并不能证明用户附件在重进会话后仍有可用入口。图片兼容块在手机上会铺开长图，不能视为用户气泡内的原生附件卡片。

## Decision

- 复用现有附件转换，只对完整的 Codex 文件包装与 Paseo 独立 Uploaded file 文本块提取绝对路径；正文任意路径不参与识别。
- 普通附件只 stat 文件元数据，生成文件名、大小及原生文件入口，不读取正文、不解压，也不占用图片缩略图预算。
- 清理包装仅影响发给 Paseo 的历史副本；保存派生文件描述，使重复转换的附件标识与输出保持稳定。原始后端消息保持不变。
- 失效文件明确提示。入口复用 Paseo 文件页，不宣称所有压缩包均可预览或下载。

## Validation

- 聚焦检查覆盖普通文件、大压缩包、失效文件、粘贴文本、混合图片与文本、独立上传块、正文路径不误识别及重复转换不增项。
- 真实当前会话的粘贴文本附件成功识别并生成可访问文件的链接；没有向用户任务发送测试提示。
- 原生手机用户消息组件有图片和附件卡片，但历史协议只提供文本与消息标识，恢复映射也没有附件字段。将图片移回用户气泡需配套修改客户端与协议，当前桥接不能单独完成。

## Alternatives considered

- 将文件内容嵌入历史：增加历史体积，大附件会重复传输。
- 将正文里所有路径转换为附件：会误识别用户讨论的路径。
- 用 Markdown 把图片塞进用户消息文本：用户消息组件渲染纯文本，不会生成图片卡片。

## Consequences

当前实现提供兼容的按需文件入口，文件读取限制与下载交互继续由 Paseo 控制。用户发送普通附件后首次显示和重进恢复的手机实际效果尚需验证；现有独立附件回复块不能解决手机长图布局问题。
