# Agent Note: 用户图片历史预览与启动配置

Status: implemented

## Problem

Paseo 的 Codex provider 从用户消息中只提取文字，历史协议也没有用户图片字段。手机上传的图片在重新加载后消失；Desktop 粘贴图片产生的路径说明则被当作普通正文显示。原始后端仍保留 localImage，图片文件也仍可读取。

直接恢复所有历史图片会使旧附件占用带宽和内存，需要明确单张、单消息及历史预览预算，并优先最近的消息。

## Decision

- JSONL shim 仅转换发送给 Paseo 的历史与用户消息事件，在原消息后追加稳定 messageId 的「用户附件」图片块。只识别明确的 localImage；不把正文中的路径自动升级为附件，不修改原后端历史或请求参数。
- 入选原图只在电脑上解码并生成长边默认 480 像素、质量 70 的 JPEG 缩略图，单张硬上限 256 KiB。图片块默认仅引用缩略图；点击「查看原图」才通过 Paseo 的现有文件预览通道读取原图，不把 Base64 塞进历史。Desktop 自动生成的附件说明仅在文件路径与真实图片记录匹配时简化；混合附件保留其他文件和用户请求。
- 启动器读取项目根目录 .env，按环境变量、文件、默认值的顺序解析并校验配置，传递给 daemon 与 shim。配置变化需要重启专用 daemon；停止服务不受错误图片配置阻碍。
- 按后端历史顺序倒序分配自动预览预算，保持最终对话原顺序。超限或失效图片提供明确占位；有效但未自动预览的图片保留文件入口。新消息独立使用预算，历史刷新重新分配。
- 配置元数据检查与缩略图生成并发为 IMAGE_PREPARE_CONCURRENCY，明确区别于无法从桥接控制的 App 下载并发。缓存标识包含原图元数据和缩略图参数，原子写入可复用，超过 128 MiB 回收旧缓存并保护当前批次。根目录 .env 被忽略，发布包只包含 .env.example；旧标签仍可使用旧文件集合构建。

## Validation

- 聚焦测试覆盖配置优先级及非法值、单图和消息限制、总预算、最新优先、失效跳过、URI 转义、原始数据不变、重复转换、历史与实时事件标识一致。
- 实际专用 daemon 重启后，Desktop 粘贴图片会话返回图片块和简化后的请求文字。通过 App 所用文件接口读取图片，与本机原图 SHA-256 相同；连续读取预览记录一致。
- 原始示例图片为 64533 字节，缩略图为 8312 字节，缓存复用检查通过。Headless Edge 重载后仅显示 480 × 120 的缩略图，点击「查看原图」后才打开 1341 × 336 的原图文件页；截图与报告保存在被忽略的 evidence 目录。手机实际操作仍需用户验证。
- 发布测试覆盖标签源码隔离、配置样例打包、旧标签兼容和缺少图片模块的拒绝路径。

## Alternatives considered

- 修改 Paseo 客户端及历史协议：可恢复原生用户附件布局，但需要重新分发手机 App；当前采用已有渲染能力兼容。
- 将图片编码放进历史：会重新扩大 RPC 响应并增加重连成本，故只传引用。
- 替换或压缩原图：会破坏截图细节；只生成独立预览，原图保持不变。
- 为桥接配置 App 下载并发或滚动事件：该层无法执行这些策略，避免提供无效配置。

## Consequences

图片在标有「用户附件」的辅助块中显示，布局不同于原生用户气泡。原生图片点击会放大当前缩略图，完整原图使用独立入口。大小限制约束自动预览，不是文件访问控制；App 和 daemon 自身也可能有更低的读取限制。文件被清理或发生变化后，预览可能失效。Windows PowerShell 辅助脚本使用 UTF-8 BOM，避免 Windows PowerShell 5 的编码误判。预览转换保留照片方向，透明背景变白、动画仅显示静态帧，真实原图不变。实际网络并发和滚动行为仍由 App 决定。
