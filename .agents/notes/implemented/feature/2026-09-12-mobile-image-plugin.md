# Agent Note: 通过 Paseo 官方插件显示紧凑图片卡片

Status: implemented

## Problem

Paseo 历史用户消息没有原生图片附件字段。桥接的 Markdown 兼容预览会被手机扩到消息宽度；降低分辨率不能限制显示尺寸，缩略图画布填充虽降低高度，却留下大块灰边。原生本地附件 ID 关联不能覆盖冷启动或跨设备恢复。

## Decision

新增可选 `paseo-plugin/`，使用官方客户端时间线转换器和 React Native 组件，把明确带桥接标识的纯图片附件行渲染为靠右的 84×84 卡片。裁掉缩略图画布填充，保留完整图片内容；点击时通过官方插件 RPC 按标识读取原图。原图按可用宽度显示，交给 Paseo 面板处理纵向滚动，横向滚动配合按钮缩放。

缩略图旁保存本地 JSON 索引，记录原图路径、大小、修改时间及裁切尺寸。手机只提交不透明标识，服务验证索引、文件状态和大小，再返回图片。默认自动读取仍遵循已有的最新消息优先预算；主动读取由 `.env` 的 `CODEY_LINK_IMAGE_OPEN_MAX_MIB` 限制，默认 20 MiB。关闭查看器后丢弃插件中的原图状态。

插件要求 Paseo 0.8.x 的客户端/服务端入口。0.7 已有基础插件时间线能力，本次没有宣称插件机制始于 0.8，也没有将当前实现反向移植。管理入口只允许操作启动器记录并再次核对的专用 daemon，不改其他服务。

实时展示同时兼容完整消息和 Markdown 分段。Paseo 0.8 的 `applyStreamEvent` 会调用 `promoteCompletedAssistantBlocks`，把旧格式的标题、图片和原图链接拆成三段；历史的 `reduceStreamUpdate` 保留整条消息。旧解析器要求三者同时出现，所以只有重新加载历史后才显示卡片。现在 `tools/image_preview.mjs` 用单换行把图片与原图入口放在同一段；插件识别无标题的完整图片段、隐藏单独的装饰性标题，并兼容已缓存的独立图片段。旧格式独立原图链接仍保留，未知内容与普通文件不被隐藏。

## Alternatives considered

- 继续调画布颜色和比例：仍由旧 Markdown 组件控制手机占位，不能得到可点击的紧凑卡片。
- 修改历史协议或重打手机 APK：需要维护上游客户端分支，部署和升级成本较大。
- 把所有附件文本转换成自定义卡片：可能吞掉普通文件、超限和失效附件的现有入口。完整的混合块保留原展示，实时拆段后仅转换确认可识别的图片。
- 要求重开 App 或反复刷新历史：只能绕过实时分段，下一张新图片仍会复现；修复应覆盖实时消息本身。

## Consequences

附件仍位于用户消息后的独立行，没有合入原生气泡。禁用插件即可恢复兼容展示。原图丢失不能由缓存重建；超限会明确拒绝，不自动传更大内容。索引含本地路径，仅存放于被忽略的运行目录。

已用官方 0.8.0 编译器编译生产入口，并验证真实 RPC 返回缩略图与原文件一致。独立 daemon 的测试界面复用生产卡片组件，在 390px Web 上检查紧凑尺寸、点击前零原图请求、点击后一次请求及长图显示；放大不重复读取，点击关闭按钮后移除原图，刷新测试页面只恢复缩略图。测试界面不连接 Codey 后端，不给用户会话发送消息。

针对实时分段，从本机正在服务的官方 0.8.0 Web bundle 加载实际流处理器、Markdown 拆段器及插件投影模块复现：旧格式产生三段，旧解析器均不识别，而历史可以识别。修复后通过桥接生成的新图片事件在实时与历史路径均得到一张卡片；追加回复后仍只保留一张，旧分段图片不再留下 Markdown 大图，普通文件入口保持可用。`tests/mobile-attachments-check.mjs` 和 `tests/image-preview-check.mjs` 固定了分段兼容与段内绑定约束。

使用该投影结果和生产卡片组件，在独立 daemon 的 390px Web 页面连续追加图片与回复，期间不刷新或重新进入页面：卡片始终为 84×84，自动原图读取与任务发送均为零，页面无脚本异常。验证后关闭独立服务，重启专用服务以加载新桥接格式和插件；保留原 Codey 后端。

专用 daemon 已切换到官方 0.8.0 并启用插件；原服务目录已备份，配对身份与会话目录保持不变，继续使用原 Codey 后端。实际长会话的 Web 历史已显示图片卡片。

用户截图已确认安卓重开 App 后可显示小卡片。本次实时分段修复仍待安卓新发图片复测，实际手势、relay 下的大图读取仍待验收。Web 通过不等于手机版全部通过，也不更新整体版本兼容结论。

聚焦验证：`node tests/settings-policy-check.mjs`；发布包白名单及旧标签重建：`python -m unittest discover -s tests -p test_release.py -v`。证据保留在被忽略的 `evidence/`，不打入发布包。
