# Agent Note: 手机长图预览限制显示高度

Status: implemented

## Problem

缩略图虽然已降低像素数，Paseo 的回复图片仍按消息宽度显示并保持原比例，竖长截图在手机上占据整屏。单纯减少分辨率不能限制显示高度。

## Decision

- 使用默认 480×240 的 JPEG 画布，原图等比居中完整展示，周围补深灰背景；透明像素所在图像区域仍用白底，不修改或裁剪原图。
- 增加 CODEY_LINK_IMAGE_THUMBNAIL_HEIGHT，范围 64–1024，实际高度不超过画布宽度。EDGE 保留原配置名，作为画布宽度。手机仍可铺满宽度，但显示高度由紧凑画布比例约束。
- 缓存标识包含新高度与布局版本，避免复用旧比例图片。原图链接简化为「查看原图」，避免手机上的散列文件名连续换行。

## Validation

- 使用用户提供的真实长截图生成 480×240 和 480×160 两种预览，检查 JPEG 尺寸、缓存复用、参数变化的缓存分离及原图 SHA-256 保持不变；默认预览为 5171 字节。
- 已查看生成图片，整张截图居中保留。配置聚焦检查覆盖默认高度、160 高度及非法零值。
- 专用 daemon 已重载；两个真实会话的历史重新生成缩略图引用，原生文件接口读取成功且字节与本机缩略图一致，重复读取的附件记录一致。手机最终布局仍待用户确认。

## Alternatives considered

- 只降低像素：App 仍会撑宽，只有清晰度下降。
- 裁剪成长方形：会丢失长截图的上下部分，采用完整等比缩放。
- 修改手机图片组件的 CSS 或布局：当前桥接不能改变已安装原生 App，先使用图片自身画布比例约束占位。

## Consequences

超长截图在缩略图内的文字会较小，阅读细节需点击「查看原图」。预览仍是独立附件块，不等于用户气泡内部附件；紧凑画布适用于 Web 和手机，手机最终操作效果需要用户确认。
