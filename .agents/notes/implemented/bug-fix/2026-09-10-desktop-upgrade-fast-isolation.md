# Agent Note: ChatGPT 升级后的 Fast 适配与故障隔离

Status: implemented

## Problem

ChatGPT 从 26.903.61454 升级至 26.903.71938 后，界面资源及管理器导出符号都发生变化。旧适配器的构建保护正确拒绝加载，但同步循环在读取 Fast 后才处理模型和推理强度，使单项适配失败扩大为整轮设置同步失败。

## Decision

[Desktop 适配器](../../../../tools/desktop_settings.mjs) 按已验证构建选择管理器导出：保留旧映射，新增新版映射。通过运行中的界面资源核对新版管理器访问器，并以 Codey 的现有作用域发现机制确认管理器及唯一 Fast 信号。未知构建继续拒绝，不能用枚举并调用所有导出来猜测访问器。

[同步进程](../../../../tools/paseo_settings_sync.mjs) 将每轮处理提取为可独立验证的函数，捕获 Fast 分支错误后继续处理实际轮次的模型与推理强度。故障期间不写 Fast 值，并清除整体档位基线，恢复时以 Desktop 状态重新建立基线，避免把失联期间的差异误当作开启请求。

## Verification

- 自动回归复现 Fast 读取错误，确认模型与强度同步继续，未发送选择不被覆盖，恢复时不把旧差异写回付费档位。
- 新版真实会话验证模型与强度双向传递及未发送选择保护。
- 原生 Fast 状态与 Paseo 完成双向开启、关闭四项实测，测试后恢复原始选择与配置。
- 使用者实际测试手机端 Fast 同步正常；其他手机显示流程及上游加速、计费不在本次验收范围内。
- 仅重启设置同步进程加载修复，原有后端与专用 daemon 保持运行。
- 后续在 `dc8def2` 上将 Codey 单独升级为 `0.10.9`，保持 ChatGPT `26.903.71938`，真实消息 / FastCtx / 重连历史、模型与强度双向同步、未发送选择保护及 Fast 双向开关再次通过，无需新增代码修改。此轮未重复手机验收，详细组合见 [兼容记录](../../../../COMPATIBILITY.md)。

## Alternatives considered

- 只放行新资源名：旧导出在新版仍是函数但语义已改变，会调用错误目标。
- 删除构建保护并动态猜测信号：未知版本缺少证据，容易误写设置。
- Fast 失败时继续中止整轮同步：扩大故障范围，基础模型设置无需依赖 Fast 适配结果。

## Consequences

新版已验证构建可以使用原生 Fast 同步，未来未知构建的失败也不再阻断模型与强度同步。仍需为结构变化重新核验映射；故障恢复时 Desktop 状态优先，失联期间仅在 Paseo 修改的 Fast 选择可能被重置。
