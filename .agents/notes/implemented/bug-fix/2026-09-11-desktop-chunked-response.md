# Agent Note: 桥接正确接收 Desktop 分片响应

Status: implemented

## Problem

Paseo 刷新长会话时调用 `thread/read` 并请求完整 turns。[现有桥接](../../../../tools/desktop_bridge.mjs) 直接读取 `MessageEvent.data`，只识别普通 `mcp-response` 等消息。Desktop 的大响应使用 `codex-host-chunked-message-v1` 分片信封，这些信封没有普通响应的 type，因此被桥接忽略，请求最终超时。

受影响会话的手机内容停留在较早轮次，刷新失败后无法补齐后续历史。本机 Paseo 历史及刷新接口同样复现。后端原始记录和原生分页接口均包含缺失内容，不能把此故障解释为手机独有或后端数据丢失。

## Decision

在 DesktopBridge 的统一消息入口，使用对应已验证 Desktop 构建的原生消息解码函数处理原始 MessageEvent，再将解码后的消息交给现有响应关联和事件订阅逻辑。

已核对当前构建 `app-initial-f094ef01c64d.js` 的导出 `Cmn`，以及旧构建 `app-initial-92cbfeba4f7c.js` 的导出 `ymn`。原生解码函数对同一个 MessageEvent 使用 WeakMap 缓存，并沿用 Desktop 的分片组装及确认机制。桥接传入原始事件，不复制事件，也不额外发送分片确认。

桥接按已核对构建维护映射，未知构建明确报告适配问题，不静默忽略分片。解码异常立即结束等待中的请求并令事件读取报错，避免只留下超时。无需修改 Paseo 手机 / Web 客户端，也无需更改后端会话文件。

ChatGPT `26.908.40834` 的构建 `app-initial-d9bed9d614d8.js` 将解码器拆至 `get-trusted-message-for-view-eee599500f15.js` 的导出 `t`。映射同时固定构建、模块文件名与导出，并检查入口依赖包含对应模块；未知分拆模块或非函数导出仍拒绝加载。继续导入原生模块而非复制实现，确保与 Desktop 共享 MessageEvent 缓存和分片确认。

安装监听器时复用现有请求 Map、线程订阅 Set 和事件队列，并在同一个同步调用中替换旧监听器。已升级运行中的三条桥接连接、保留四个订阅，随后调用 Paseo 原生刷新接口；无需重启 daemon 或原 Codey 后端。

## Evidence

- 原始桥接：元数据读取约 6 ms；完整历史约 35 秒超时。单独观察 120 秒仍收不到桥接认可的响应。
- 原生分页：75 次小请求在约 790 ms 内读取 28 轮、1138 条记录，未发现重复 item ID，缺失时段的后续内容存在。
- 单次完整 turns 请求同样超时，说明仅换接口名不能解决大响应接收问题。
- 隔离探针复用原生解码器后，同一个 `thread/read` 在约 489 ms 完成：收到 9 个分片、还原 1 个响应，包含 28 轮、1138 条记录，JSON 约 5.82 MB。
- 隔离探针退出时移除自己的监听器，根因确认后才将同一解码路径接入正式桥接。

## Alternatives considered

- 只延长超时：桥接忽略分片，等待更久也无法关联响应，120 秒探针已复现。
- 在 shim 中分页重建全量 thread/read：可绕开本例的大响应，但不能覆盖其他方法的大响应和大事件，还需要处理游标、顺序、并发轮次与完整性；作为兼容性后备方案。
- 自行实现分片协议并发送确认：与原生消费者竞争，容易重复确认或误组装；优先复用已验证的原生解码器。
- 修改手机缓存或删除会话：本机接口也失败，且后端数据完整，无法解决协议缺失。

## Verification

- 回归覆盖普通 / 分片响应关联、同一事件缓存复用、订阅过滤、监听器替换时保留请求与队列，以及解码错误和未知构建的显式失败；测试由既有 settings-policy-check 入口执行。
- 正式桥接读取完整目标历史约 606 ms；Paseo 历史接口约 1699 ms、刷新接口约 2649 ms，均成功。
- 三次断开重连并重新订阅后，最近 100 条投影记录的完整哈希一致。
- Paseo 最新助手回复与后端最新回复文本完全一致，目标会话已补齐至北京时间 2026-09-11 16:42:37 的记录。
- 保留原后端与 daemon，未修改原始会话文件。旧构建核对来自保留源码，本轮未切换旧应用做实机回归。
- `26.908.40834` 修复验证：旧构建与新独立模块通过动态导入测试，未知模块和无效导出明确失败。正式桥接读取 89 轮、约 6 MB 历史约 594 ms，Paseo 原生时间线尾页读取成功；独立会话的真实消息、FastCtx 文件读取和重连历史恢复通过。使用升级后已有的 Codex CLI `0.154.0-alpha.6.2`，未另建普通后端。
- 用户确认此次升级修复后的手机验证通过，同意将该版本组合记录为已通过并发布 `0.0.3`；不扩大到未检查的其他客户端版本或长时间运行场景。

## Consequences

大响应现在与普通响应共用同一分发路径，避免为各个历史读取 API 分别实现绕行。原生导出属于 Desktop 内部接口，升级后仍需核对映射。完整响应在 bridge 与 Paseo 间仍可能较大；修复分片接收不等于完成任意超长会话的内存和延迟优化。服务端恢复及重连检查已完成，手机实际显示以用户重载后的验收为准；未在用户正在工作的目标会话发送额外测试消息。
